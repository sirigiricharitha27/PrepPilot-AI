# PrepPilot AI — student learning companion

A local Node.js web app with separate Learn & Improve and exam-style Test modes, student progress reports, a concept map, revision suggestions, explain-back practice, question reporting, and an AI Study Buddy interface.

## Run locally

Requirements: Node.js 18+ (Node 20+ recommended). No npm packages are required.

1. Extract this ZIP.
2. Open a terminal in the `preppilot` folder.
3. Run `node server.js`.
4. Open http://localhost:3000.

To use another port: `PORT=3123 node server.js` (Windows PowerShell: `$env:PORT=3123; node server.js`).

## Content coverage

The app provides a starter practice bank across Classes 1–10 and Mathematics, Science, Physics, Chemistry, Biology, Social Studies, and English. The six-question set is age-banded (Classes 1–3, 4–6, and 7–10) and includes answers, hints, and explanations. Physics, Chemistry, and Biology currently share the general Science starter set. This is useful demonstration content, **not an exhaustive or officially verified mapping to every CBSE, ICSE, or State Board chapter**. Review content before any classroom or public use.

## Features

- Responsive student-first interface; no teacher dashboard.
- Class, curriculum, subject and Easy/Medium/Hard selection.
- Learn mode with hints, answer feedback, retries, simpler explanations, read-aloud, supported speech input, and question reporting.
- Test mode hides feedback during the assessment, then provides a scorecard and answer review.
- Learning report with practice accuracy, test percentages/history, concept progress and print-to-PDF export.
- Mastery map, revision suggestions, explain-back and AI Study Buddy text/image UI.
- Browser-local persistence for student profile and progress.

## AI Study Buddy and AI configuration

The AI Study Buddy calls the BharatCode chat-completions API from the Node.js server. If `BHARATCODE_API_KEY` is not configured, the app falls back to built-in demo responses; these are not generated by a general-purpose AI model. The API key is read only by the server and should never be placed in frontend code or committed to a public repository. API access and usage limits depend on your BharatCode account.

Image-question support depends on the model/API accepting the image payload used by the app and should be tested with your configured account before making claims about it. Speech input depends on browser support; text entry remains available.

## BharatCode API setup (Windows PowerShell)

Set the key in the same PowerShell window before starting the server:

```powershell
$env:BHARATCODE_API_KEY="YOUR_BHARATCODE_KEY"
node server.js
```

Optional settings are listed in `.env.example`. It is a template only; the actual API key should be entered as an environment variable locally or in your hosting provider's secret settings. Never paste the key into chat, frontend files, README, or a public repository.

## Data and privacy

Profile, learning history, test records and question reports are stored in the browser's local storage on that device. This demo does not provide secure multi-user accounts or cloud syncing. Do not enter sensitive personal information.

## Validation performed

- JavaScript syntax checked with `node --check`.
- Server health and homepage routes checked.
- API question banks checked for all 10 classes × 7 subject selections (70 combinations; six questions each).
- Built-in assistant fallback checked.

A full interactive browser test across every possible device/browser has not been performed. Please review educational content and test the main user journey before public deployment or hackathon submission.


## Accounts and progress
- Create an account with an email address and password (minimum 8 characters), or sign in to an existing account.
- Passwords are stored as salted scrypt hashes; plaintext passwords are not saved.
- Learning progress is stored per account in `user-data/users.json` on the server. Do not publish this generated data file; it is excluded from Git.
- Sign out using the button in the top-right corner.
- This is a local/demo account system, not a production identity provider. Sessions are held in memory and signing out or restarting the server invalidates active sessions. For public deployment, use HTTPS and a production-grade session store, rate limiting, email verification and account recovery.
- A fresh account starts with a clean progress record. Existing browser localStorage is no longer used as the source of truth.
